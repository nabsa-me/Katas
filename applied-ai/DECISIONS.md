## Decisions

- **One kata, two package managers.** `applied-ai` is an npm project (`package.json`, `package-lock.json`) and a uv project (`pyproject.toml`, `uv.lock`, `.python-version`) at the same root, because the Bedrock exercise has a Python twin. The Python files live in `src/exercises/claude-bedrock/python/` with snake_case module names (Python imports require them); pytest's `pythonpath` points there. The Python project files were committed with the Bedrock exercise, the only one that uses them (approved deviation from "Python files in the scaffold").
- **The Bedrock Converse API with the AWS SDKs**, as asked: `@aws-sdk/client-bedrock-runtime` and `boto3`. Anthropic's own SDK has a Bedrock client (`AnthropicBedrockMantle` in `@anthropic-ai/bedrock-sdk`, `from anthropic import AnthropicBedrockMantle` in Python) that speaks the Messages API on Bedrock; it is the alternative when a project already uses the Anthropic SDK.
- **Model id from the environment**, default `global.anthropic.claude-opus-5-5` (the global cross-Region inference profile; the in-Region id is `anthropic.claude-opus-5-5`). Prices live in `pricing.json`, keyed by the exact id, with a note that they are illustrative and must be checked on the Bedrock pricing page (the values used are Anthropic's published first-party prices); every cost in logs and reports is labelled "estimated", and an unknown id gives `null`.
- **`NodeHttp2Handler` instead of `NodeHttpHandler`** (approved deviation from the plan). Bedrock Runtime's default handler is `NodeHttp2Handler` with `disableConcurrentStreams: true` and no request timeout (a stalled request waits for the session's five-minute idle timeout); passing `NodeHttpHandler` would silently switch to HTTP/1.1. The client keeps the same handler and adds `requestTimeout`. A local h2c server (`fake-bedrock-server.ts`) runs the real SDK, so retries, backoff and timeouts are the SDK's own.
- **Python twin:** `Config(connect_timeout, read_timeout, retries={"mode": "standard", "total_max_attempts": n})`; `total_max_attempts` counts the first call, `max_attempts` only retries. The tool lives in `issue_tool.py`, separate from `bedrock_converse.py`, to keep each module short. botocore's `Stubber` validates responses against the service model and cannot express an event stream, so the ConverseStream test uses a minimal fake client (deviation).
- **Reasoning blocks are sent back untouched.** Claude Opus 5.5 always reasons; Converse may return `reasoningContent` blocks, and the loop appends the assistant message exactly as received. The requests set no `temperature`, `topP` or forced `toolChoice`, which the Claude API rejects for this model.
- **MCP server:** `McpServer.registerTool` with zod 4 shapes, a read tool (`readOnlyHint: true`) and a write tool (`readOnlyHint: false`, `destructiveHint: false`, `idempotentHint: false`), both `openWorldHint: true`. Handlers never throw: a wrapper turns every failure into an `isError` result with a message chosen by status, and logs the stack to stderr. Jira is reached through a small client with Basic auth, a 10 s timeout per request and zod-validated responses; the configuration is validated at startup.
- **MCP stdio entry in `stdio.ts`**, separate from `server.ts` (approved deviation): `createJiraMcpServer()` does not know its transport, so the tests connect it through `InMemoryTransport` and a remote deployment would connect it to `StreamableHTTPServerTransport`. One test starts `stdio.ts` as a real child process with `StdioClientTransport`, from the system temp folder, with the same command the `.mcp.json` example uses (`node <kata>/node_modules/tsx/dist/cli.mjs <kata>/src/exercises/mcp-server/stdio.ts`).
- **`.mcp.json` uses `${VAR}` expansion and `${CLAUDE_PROJECT_DIR:-.}`**, verified in the Claude Code MCP documentation: expansion works in `command`, `args`, `env`, `url` and `headers`, an unset variable stays literal with a warning, and `CLAUDE_PROJECT_DIR` needs a default in project entries. No `.mcp.json` is committed: the README shows it, so opening the folder in Claude Code does not prompt to approve a server.
- **Skill helper in plain JavaScript**: `check-pending-migrations.mjs` has no dependencies, because a plugin is copied as files with no install step. It is type-checked from its JSDoc through `allowJs` and `checkJs` in `tsconfig.app.json` (approved deviation) and `// @ts-check`. It supports dbmate's layout (`<version>_<name>.sql`, one file per migration) and reads the applied versions from a file, so it never needs database credentials.
- **Plugin evals are included but not run.** The plugin has two `claude plugin eval` cases (one must trigger the skill, one must not), written in the format the CLI 2.1.330 documents (`prompt.md` with `max_turns`, `timeout_seconds`, `allowed_tools`, `runs`; graders `tool_used` and `llm`). They call the model, so `npm test` only checks that they are well formed; `claude plugin validate --strict` passes on the marketplace and on the plugin.
- **Evals:** one `TextModel` interface for the feature, the CI mock and the Bedrock adapter, so the eval runs the product's code path. The CI gate uses a deterministic keyword model and a deterministic judge that applies the checkable part of the rubric; both are deliberately imperfect so the report has failures to read. Their token counts are priced as the default Bedrock model, so the report forecasts a real run's cost. `EVAL_MODEL=bedrock` reuses the claude-bedrock client (timeout and retries) and `EVAL_JUDGE_MODEL_ID` can point the judge at another model. The percentile is nearest-rank. Cases run sequentially to stay within rate limits.
- **Logging:** pino with one JSON line per model call or tool call, the level as a word and an ISO time, redaction of `authorization` and `apiToken`; CLIs and the stdio server log to stderr.
- **Flawed versions** (`*.problem.ts`, `release-process.problem.md`) are tested next to the solutions. The MCP problem file keeps its untyped code and disables `@typescript-eslint/no-explicit-any` at the top with the reason.
- **No real credentials anywhere**: AWS credentials only in the tests' fake signer (`replace-with-…`), Jira tokens as placeholders, no AWS key or token formats.
- **Branch base:** the worktree branch was fast-forwarded to the tip of `kata/ssr-fullstack` (08b3f36) before the first commit.

- ⚠️ The prices in `pricing.json` are Anthropic's first-party prices used as illustrative values; Bedrock's prices may differ by Region and profile: https://aws.amazon.com/bedrock/pricing/
